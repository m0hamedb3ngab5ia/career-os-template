# careeros CLI and API reference

Moved out of `CLAUDE.md` to keep agent context small; `CLAUDE.md` points here.

- API `GET /api/catalogue` (REQ-165) -> `docs/CATALOGUE.md` parsed to `{intro, sections:[{title, rows:[{feature, what, how, req}]}]}` (tables only, backticks kept); 404 if the file is missing. The UI shows it at `/catalogue`, linked from Today's header and the sidebar
- `.venv/bin/careeros scout --sync` — pull boards (the `simplify` board is the SimplifyJobs new-grad `listings.json`: last `window_days` days; Greenhouse/Ashby/Lever links become that ats and skip jobs already found, other ATSs are stored as `other`), prefilter (also `location.work_modes`, `scout.max_post_age_days` and `scout.new_grad_max_post_age_days` for new-grad titles), store, sync tracker, write `data/scout_last.json` (what each filter removed)
- `.venv/bin/careeros company find-board <name>... [--file names.txt] [--json]` — probe Greenhouse/Ashby/Lever for each company (slug guesses from the name), print `boards:` lines to paste into `config/companies.yaml` (names already there are skipped). Generic names can hit another company: check a hit's job titles before adding it
- `.venv/bin/careeros outreach targets [--top 3] [--status applied queued] [--min-fit N] [--json]` — high-yield jobs for outreach without an `outreach.json` yet, one per company: tier `outreach: always` at any fit, `if_contact_found` at `pipeline.yaml: outreach.min_fit` (80) or more; best fit first. Then per job `/find-contacts <id>` → `/draft-outreach <id>`. `outreach emails <job_id> [--domain D] [--no-apollo] [--enrich 2] [--no-hunter]` — fill `contacts.json` (creates it if missing). Optional Apollo.io first (`careeros creds set apollo --password-stdin`): people search at the domain (0 credits), then email for up to `--enrich` people, recruiters first (1 credit each); refused (403, free API needs a work-email account) → manual `search_urls.apollo_*` links to open yourself. Credits used are logged to the job's `log.md`. Then email guesses: domain (`company_domains`, posting URL unless an ATS, else the domain already in `contacts.json` when high|medium, else `<name>.com` low), common patterns, and with your own Hunter.io key (`careeros creds set hunter --password-stdin`, free tier, sent as a header) the company's real pattern, exact addresses (`medium`, never `verified`, so never auto-sent) and recruiters it knows. Writes a manual `verify_tip` (Gmail compose photo check); never probes or sends
- `.venv/bin/careeros network import <Connections.csv>` — load your own LinkedIn export (Settings → Data privacy → Get a copy of your data → Connections) into gitignored `data/network.json`, replacing it; rows without a company are dropped. `network match [--status S...] [--job ID] [--actions] [--json]` — jobs (default scored, queued, prepared, needs_review) at a company where you have a 1st-degree connection, best fit first; companies match by normalized name + `company_caps` aliases. `--actions` adds one deduped `referral` Action Item per job. Exit 1 = no network imported. Never touches LinkedIn
- `.venv/bin/careeros jobs list [--status queued]`, `job show <id>`, `job add <url>` (Greenhouse/Lever/Ashby link via the scout adapter, other pages as `ats: manual`, Handshake refused; same job ids as scout so repeats say `exists`; exit 1 on failure), `job add --from-alert <file|->` (JSON `[{title, company, url}]` from LinkedIn/Indeed alert emails, no fetch, used by inbox-sync), `job describe <id> --text-file <path|->` (pasted posting text for a job added from an alert; clears `needs_description` so it can be scored; exit 1 if the job is unknown or the text empty), `job status <id> <status> [--note] [--channel cold|referral|sourced|hm_dm] [--referral-contact ID]` (status.json + tracker; channel + contact kept in status.json and the history entry, `jobs list --json` shows `channel`, default cold), `yield report [--json]` (per channel: resolved applications, interviews, rate, Wilson 95% interval, screenings counted apart, censored = started <45 days ago with no interview or rejection, left out of the rate), `jobs recredit [<id>...] [--min-fit 0] [--write] [--json]` (low-fit skips: move a missing skill to matched only when the profile evidences it, directly, via `match.synonyms` or one-way `match.implies`, with the evidence id; recompute skills_overlap, fit, tier and decision; a skip that now meets the current `thresholds.min_fit_to_prepare` flips even with nothing credited, so lowering the cutoff applies to old skips; dry run unless `--write`, which resets flipped jobs to `scored`), `job filters <id>` (score-job's hard filters in code: exit 3 = dealbreaker, writes a skip `score.json` with fit 0; exit 0 = none hit; output also has `pay_exempts_location`: posted minimum base >= `thresholds.any_location_min_base_usd`, which lifts the non-preferred-location rule; fail `location_nonpreferred` when `thresholds.min_fit_nonpreferred_location` > 100 and the posting is a US state outside `location.preferred` + `preferred_regions`, unparseable = no fail), `stats`, `action list`, `action add "<what>" --type <t> --needs laptop|phone|anytime`
- `.venv/bin/careeros learn answer "<question>" "<answer>" [--job <id>] [--key k] [--match re ...] [--company X] [--eeo]`, `learn lesson "<text>" [--ats workday|greenhouse|lever|ashby|custom] [--company X] [--job <id>] [--tag t]`, `learn list [--ats] [--company] [--json]` — answers land in `profile/standard_answers.yaml`, hurdles in `profile/apply_lessons.yaml`; `action done <id> --answer "<text>"` learns a question/salary item's answer, then closes it
- `.venv/bin/careeros tracker applied-count [<company>] [--days N]`, `tracker upsert <job_id> --field Header=value ...`, `tracker sync|flush|init` (workbook: Jobs has a plain-English `Reason` after `Status`; status `skipped` jobs live on the `Skipped` tab with `Posting` open|closed, closed rows dropped at `sync` per `retention.tracker_closed_after_days`; a status change off skipped moves the row back to Jobs; old layouts are rebuilt on first write)
- `.venv/bin/careeros run score|prepare [--preset small|medium|large|max|custom] [--max-jobs N] [--max-minutes M] [--dry-run] [--json]` — budgeted batches, one headless skill call per job, never applies; a `run score` job the hard filters (`job filters`) reject is skipped in code first (skip score.json, status `skipped`, attempt outcome `prefiltered`, no session, no budget slot; `--dry-run` lists them); `runs.parallel.score: N` (pipeline.yaml, default 1) scores up to N jobs at once (budget, pause/cancel, daily cap and stop rules checked before each launch, jobs in flight count toward `--max-jobs`; `runs.parallel.prepare: N` (default 1) does the same for prepare, never running two jobs of one company together and counting jobs in flight toward the daily cap; apply and `--job` runs stay one at a time); `--job <id> [--force]` runs one job (exit 2 with the reason if it is not a candidate); `run score` takes `--job` repeatedly and never ticks the jobs (REQ-137), `prepare`/`apply` `--job` still ticks (REQ-104); API `POST /api/jobs/score {job_ids}` = Score now: one score run over exactly those jobs -> `{run_id, kind}` (404 unknown id, 409 not runnable)
- `.venv/bin/careeros apply plan <job_id> [--json] [--schema-json PATH] [--lock-token T|--force]` — Greenhouse or Ashby (dispatch on `posting.ats`; Ashby = jobs.ashbyhq.com non-user GraphQL `ApiJobPosting` form schema, field_id = Ashby field path, booleans Yes/No, EEO survey not in schema so left blank, `--schema-json` takes the GraphQL response) question schema -> `data/jobs/<id>/fill_plan.json` (legal/salary/EEO unanswered pause, sensitive = exit 3); `apply fill <job_id> [--cdp http://localhost:9222] [--url U] [--lock-token T|--force]` — stages the plan in the browser via Playwright (`pip install -e '.[fast-apply]'`), reads every value back -> `fill_summary.json` + 1 screenshot; refuses blocked/unanswered plans; never submits. Selects: degree level -> "<Level>'s Degree", `education.discipline` may be a list (first offered wins), start/end month+year, phone country from `identity.phone`; standard answers take optional `prefer: [keywords]`. The filled tab stays open in a detached browser (CDP `paths.apply_cdp`, default 127.0.0.1:9223; `application.json` records it); UI `GET/POST /api/jobs/{id}/application[/open]` = liveness / focus-or-refill
- `.venv/bin/careeros creds set <site> [--username U] [--notes N] [--password-stdin|--no-password]`, `creds get <site> [--json|--reveal]`, `creds list [--json]` (no secrets), `creds rm <site>` — ATS/job-site logins for `/apply-job` in `paths.credentials` (default `~/.careeros/credentials.yaml`, 0600, outside git; `credentials.backend: file|keychain`); run logs mask stored passwords
- `.venv/bin/careeros resume annotations <rid>` (draft `{rev, resume, draft}` + `items`), `resume annotate <rid> suggestion|comment [--target <bullet id|field>] [--proposed "<text>"] [--text "<text>"]`, `resume annotate-reply <rid> <aid> "<text>"` — AI annotations (author=ai, DEC-016) written by `review-resume` / `edit-resume`; they only propose and reply, the user accepts in the UI; run kinds `review`, `resume_edit` (Read + `careeros` only). `resume rule-add "<heading>" "<rule>"` saves one general rule to `profile/resume_feedback.md` (dedupes; exit 1 on numbers or a confidential term; allowed for `resume_edit`, not `review`)
- (legacy, the current UI's review popup) `.venv/bin/careeros resume feedback <rid>`, `resume review-save <rid> <items.json>`, `resume apply-edit <rid> <item> <base> <text>` (zero-fabrication guard; exit 1 = refused or `<base>` not the latest), `resume redraft <rid> <item> "<suggestion>"` (hand edit = UI only, PUT .../text) — the old review/edit lifecycle (REQ-094..097), kept for the current UI only; `review-resume` / `edit-resume` now write annotations (`resume annotate`, above). A new master version launches `extract_master`
- `.venv/bin/careeros run apply --job <id> [--json]` — `/apply-job` one prepared job headless (Chrome MCP tools allowed); `--job` required, Tier A staged for review, never submitted, never scheduled
- `.venv/bin/careeros batch create <job_id>... --stop-at score|prepare|fill|submit [--job-stop J=STAGE ...] [--name N] [--dry-run] [--json]`, `batch show <id> [--json]` — plan a batch (`data/runs/batches/<id>.json`): per-job first stage + exclusion reasons; per-job stops capped server-side (LinkedIn Easy Apply apply URL / readiness open -> prepare, Tier A -> fill; flagged excluded), Tier A never auto-submitted, one job per run; `batch run <id>` (driver: one job at a time, one run per stage, re-checks LinkedIn + auto-submit before each apply; exit 6 = running), `batch pause|cancel <id>`, `batch retry <id> [--job J]`
- `.venv/bin/careeros resume shortlist <job_id> [--json]` — deterministic bullet shortlist (greedy weighted cover of the posting's required/preferred skills by non-placeholder master bullets, inside the one-page budget) -> `JOB/bullet_shortlist.json`: bullet ids per entry with the keywords each covers, uncovered keywords, listed skills without bullet evidence. `--compare` (no job id): required-keyword coverage of the shortlist vs the existing résumé over QA-passed jobs. No LLM; tailor-resume starts from it.
- `.venv/bin/careeros resume match <job_id> [--threshold N] [--json]` — deterministic match score 0-100 of every résumé (latest version) vs the job, best first, missing skills (DEC-003; `targets.yaml: thresholds.min_match`, `pipeline.yaml: match.synonyms`); API `GET /api/jobs/{id}/matches[?threshold=N]`
- `.venv/bin/careeros run list|show <id> [--json|--log]|status|cap [--check]|pause [--until +2h|ISO] [--reason]|resume|catch-up [--dry-run|--dismiss]`
- `.venv/bin/careeros job select|unselect <id>...` (REQ-104: new postings start unticked; prepare/apply runs and tick take only ticked jobs; `run prepare|apply --job X` ticks X (`run score --job` does not); `batch create` takes the jobs it names (Jobs-table selection, Q-022) and ticks them, untick mid-run holds a job back; API `POST /api/jobs/select`)
- `.venv/bin/careeros outreach sent <job_id> [--contact NAME] [--date YYYY-MM-DD]` — record a message you sent by hand: sets `sent`, `sent_by: candidate`, `sent_at` on the matching drafts in `outreach.json` (all drafts without `--contact`). Starts the follow-up clock (REQ-154); career-os never sends
- `.venv/bin/careeros outreach qa <job_id> [--contact NAME] [--line TEXT]` — gate outreach drafts (≤80 words, sourced fact, bullet id, ask, banned phrases); `--line` stores your own sentence; a draft is `ready` only with it. Prints a prefilled Gmail compose link per ready email (you press send; REQ-162). Exit 1 on problems
- `.venv/bin/careeros notify setup [--email E]|test|digest [--dry-run]` — daily/weekly email digest to yourself (REQ-155). `setup` hands the Gmail app password to macOS `security` (Keychain `careeros-smtp`); then set `pipeline.yaml notify: {enabled: true, email, digest: daily|weekly|off, weekly_day, send_at, urgent}`. `careeros tick` sends it; `tick` also raises the 14-day reach-out item per applied job (REQ-156), and, for new scored jobs at watched companies (dream_list or `boards[].watch: true`), an Urgent Today item + one urgent email when fit >= `notify.urgent_min_fit` (REQ-159). Season windows: `targets.yaml volume.season_multiplier` list form (REQ-160)
- `.venv/bin/careeros job lock|unlock|check <id>` (exit 6 = held), `tick [--dry-run]` (also raises/closes `follow_up` Action Items: applied jobs and sent outreach with no reply after `follow_ups.after_days`, default 7; REQ-154), `schedule install|uninstall|status` (LaunchAgent → `careeros tick`)
- `.venv/bin/careeros ui [--port 8765] [--reindex] [--no-open]` — local web app on 127.0.0.1 (needs `pip install -e ".[ui]"` + `playwright install chromium` for Fill application); SQLite index `data/careeros.db` is disposable
- `.venv/bin/careeros resume list [--json]`, `resume add <file.pdf|docx> [--name N] [--type master|variant|other|tailored] [--json]` — résumé store `profile/resumes/<rid>/` (meta.json + v<n>/original, text.txt, ats.json); first résumé = master; the other résumé API routes were removed (DEC-024), only `GET /api/profile/master/proposal` and `POST .../proposal/approve|reject` remain
- `.venv/bin/careeros resume propose-master <file>` (extract-master: proposal → `profile/master.proposed.yaml`, pending until approve/reject), `resume keep-master` (keep `profile/master.yaml` as is: drops any pending/rejected proposal, records the master résumé in `master.synced.json`, closes readiness `master_synced`; exit 1 without a master résumé)
- `.venv/bin/careeros resume look-check` — exit 0 when the master résumé look is approved, else exit 7 (prepare-job Step 0; REQ-143)
- `.venv/bin/careeros resume approve-look` — records that you saw and approved how the master résumé looks (`profile/master.look.json` {rid, version, approved_at}); prints where its PDF is. Closes readiness `resume_look_approved` (prepare and apply exit 7 until then); a new master résumé or version resets it; exit 1 without a master résumé
- `.venv/bin/careeros view [--open]` — writes `data/views/<tab>.html` from data on disk (no AI, no network), linked as tabs: Setup checklist until its must-items are done, then Documents (résumés, saved answers, writing samples); Jobs (open action items, jobs by stage, last runs); Search (every job-search filter, its value, a sentence to say in chat to change it, and how many new postings each filter removed in the last `scout`, read from `data/scout_last.json`); Applications (newest first, 50). Prints the first tab's path, `--open` opens it
- `.venv/bin/careeros prune [--yes]`, `storage [--json] [--snapshot]`, `advise [--json]` (also skip reasons, near-miss skills, filter unlock counts), `advise apply <id>` (suggest-only; writes config/pipeline.yaml only on apply)
- `.venv/bin/careeros sync status [--remote template] [--no-fetch] [--json]|pull [--branch B] [--no-checks]|install-hook [--force]` — private copy vs the public template (status exit 0 in sync, 1 behind, 2 drift; pull exit 3 = conflicts; `.template-sync-keep` lists intentional differences)
- `.venv/bin/python -m careeros.qa data/jobs/<id>` — deterministic QA
- `.venv/bin/python templates/resume/render.py data/jobs/<id>/resume.json` — tex+pdf+txt
- `.venv/bin/python -m pytest -q`
- `.venv/bin/careeros safety ghost-items [--close-stale] [--dry-run]` — one `ghost_job` Action Item per dream company, listing its scored jobs that pass hard filters, meet `thresholds.min_fit_to_prepare` and still trip a ghost review flag (`safety check` no longer adds items). `--close-stale` first marks done, with a note and never deleting, open per-job `ghost_job` items the current rule would not raise; `--dry-run` (with it) only counts. Idempotent.
