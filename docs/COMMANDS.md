# careeros CLI and API reference

Moved out of `CLAUDE.md` to keep agent context small; `CLAUDE.md` points here.

- `.venv/bin/careeros scout --sync` — pull boards, prefilter (also `location.work_modes` and `scout.max_post_age_days`), store, sync tracker, write `data/scout_last.json` (what each filter removed)
- `.venv/bin/careeros jobs list [--status queued]`, `job show <id>`, `job status <id> <status> [--note]` (status.json + tracker), `job filters <id>` (score-job's hard filters in code: exit 3 = dealbreaker, writes a skip `score.json` with fit 0; exit 0 = none hit; output also has `pay_exempts_location`: posted minimum base >= `thresholds.any_location_min_base_usd`, which lifts the non-preferred-location rule; fail `location_nonpreferred` when `thresholds.min_fit_nonpreferred_location` > 100 and the posting is a US state outside `location.preferred` + `preferred_regions`, unparseable = no fail), `stats`, `action list`, `action add "<what>" --type <t> --needs laptop|phone|anytime`
- `.venv/bin/careeros learn answer "<question>" "<answer>" [--job <id>] [--key k] [--match re ...] [--company X] [--eeo]`, `learn lesson "<text>" [--ats workday|greenhouse|lever|ashby|custom] [--company X] [--job <id>] [--tag t]`, `learn list [--ats] [--company] [--json]` — answers land in `profile/standard_answers.yaml`, hurdles in `profile/apply_lessons.yaml`; `action done <id> --answer "<text>"` learns a question/salary item's answer, then closes it
- `.venv/bin/careeros tracker applied-count [<company>] [--days N]`, `tracker upsert <job_id> --field Header=value ...`, `tracker sync|flush|init`
- `.venv/bin/careeros run score|prepare [--preset small|medium|large|max|custom] [--max-jobs N] [--max-minutes M] [--dry-run] [--json]` — budgeted batches, one headless skill call per job, never applies; a `run score` job the hard filters (`job filters`) reject is skipped in code first (skip score.json, status `skipped`, attempt outcome `prefiltered`, no session, no budget slot; `--dry-run` lists them); `runs.parallel.score: N` (pipeline.yaml, default 1) scores up to N jobs at once (budget, pause/cancel, daily cap and stop rules checked before each launch, jobs in flight count toward `--max-jobs`; prepare/apply and `--job` runs stay one at a time); `--job <id> [--force]` runs one job (exit 2 with the reason if it is not a candidate); `run score` takes `--job` repeatedly and never ticks the jobs (REQ-137), `prepare`/`apply` `--job` still ticks (REQ-104); API `POST /api/jobs/score {job_ids}` = Score now: one score run over exactly those jobs -> `{run_id, kind}` (404 unknown id, 409 not runnable)
- `.venv/bin/careeros apply plan <job_id> [--json] [--schema-json PATH] [--lock-token T|--force]` — Greenhouse question schema -> `data/jobs/<id>/fill_plan.json` (legal/salary/EEO unanswered pause, sensitive = exit 3); `apply fill <job_id> [--cdp http://localhost:9222] [--url U] [--lock-token T|--force]` — stages the plan in the browser via Playwright (`pip install -e '.[fast-apply]'`), reads every value back -> `fill_summary.json` + 1 screenshot; refuses blocked/unanswered plans; never submits. Selects: degree level -> "<Level>'s Degree", `education.discipline` may be a list (first offered wins), start/end month+year, phone country from `identity.phone`; standard answers take optional `prefer: [keywords]`. The filled tab stays open in a detached browser (CDP `paths.apply_cdp`, default 127.0.0.1:9223; `application.json` records it); UI `GET/POST /api/jobs/{id}/application[/open]` = liveness / focus-or-refill
- `.venv/bin/careeros creds set <site> [--username U] [--notes N] [--password-stdin|--no-password]`, `creds get <site> [--json|--reveal]`, `creds list [--json]` (no secrets), `creds rm <site>` — ATS/job-site logins for `/apply-job` in `paths.credentials` (default `~/.careeros/credentials.yaml`, 0600, outside git; `credentials.backend: file|keychain`); run logs mask stored passwords
- `.venv/bin/careeros resume annotations <rid>` (draft `{rev, resume, draft}` + `items`), `resume annotate <rid> suggestion|comment [--target <bullet id|field>] [--proposed "<text>"] [--text "<text>"]`, `resume annotate-reply <rid> <aid> "<text>"` — AI annotations (author=ai, DEC-016) written by `review-resume` / `edit-resume`; they only propose and reply, the user accepts in the UI; run kinds `review`, `resume_edit` (Read + `careeros` only). `resume rule-add "<heading>" "<rule>"` saves one general rule to `profile/resume_feedback.md` (dedupes; exit 1 on numbers or a confidential term; allowed for `resume_edit`, not `review`)
- (legacy, the current UI's review popup) `.venv/bin/careeros resume feedback <rid>`, `resume review-save <rid> <items.json>`, `resume apply-edit <rid> <item> <base> <text>` (zero-fabrication guard; exit 1 = refused or `<base>` not the latest), `resume redraft <rid> <item> "<suggestion>"` (hand edit = UI only, PUT .../text) — the old review/edit lifecycle (REQ-094..097), kept for the current UI only; `review-resume` / `edit-resume` now write annotations (`resume annotate`, above). A new master version launches `extract_master`
- `.venv/bin/careeros run apply --job <id> [--json]` — `/apply-job` one prepared job headless (Chrome MCP tools allowed); `--job` required, Tier A staged for review, never submitted, never scheduled
- `.venv/bin/careeros batch create <job_id>... --stop-at score|prepare|fill|submit [--job-stop J=STAGE ...] [--name N] [--dry-run] [--json]`, `batch show <id> [--json]` — plan a batch (`data/runs/batches/<id>.json`): per-job first stage + exclusion reasons; per-job stops capped server-side (LinkedIn Easy Apply apply URL / readiness open -> prepare, Tier A -> fill; flagged excluded), Tier A never auto-submitted, one job per run; `batch run <id>` (driver: one job at a time, one run per stage, re-checks LinkedIn + auto-submit before each apply; exit 6 = running), `batch pause|cancel <id>`, `batch retry <id> [--job J]`
- `.venv/bin/careeros resume match <job_id> [--threshold N] [--json]` — deterministic match score 0-100 of every résumé (latest version) vs the job, best first, missing skills (DEC-003; `targets.yaml: thresholds.min_match`, `pipeline.yaml: match.synonyms`); API `GET /api/jobs/{id}/matches[?threshold=N]`
- `.venv/bin/careeros run list|show <id> [--json|--log]|status|cap [--check]|pause [--until +2h|ISO] [--reason]|resume|catch-up [--dry-run|--dismiss]`
- `.venv/bin/careeros job select|unselect <id>...` (REQ-104: new postings start unticked; prepare/apply runs and tick take only ticked jobs; `run prepare|apply --job X` ticks X (`run score --job` does not); `batch create` takes the jobs it names (Jobs-table selection, Q-022) and ticks them, untick mid-run holds a job back; API `POST /api/jobs/select`)
- `.venv/bin/careeros job lock|unlock|check <id>` (exit 6 = held), `tick [--dry-run]`, `schedule install|uninstall|status` (LaunchAgent → `careeros tick`)
- `.venv/bin/careeros ui [--port 8765] [--reindex] [--no-open]` — local web app on 127.0.0.1 (needs `pip install -e ".[ui]"` + `playwright install chromium` for Fill application); SQLite index `data/careeros.db` is disposable
- `.venv/bin/careeros resume list [--json]`, `resume add <file.pdf|docx> [--name N] [--type master|variant|other|tailored] [--json]` — résumé store `profile/resumes/<rid>/` (meta.json + v<n>/original, text.txt, ats.json); first résumé = master; the other résumé API routes were removed (DEC-024), only `GET /api/profile/master/proposal` and `POST .../proposal/approve|reject` remain
- `.venv/bin/careeros resume propose-master <file>` (extract-master: proposal → `profile/master.proposed.yaml`, pending until approve/reject), `resume keep-master` (keep `profile/master.yaml` as is: drops any pending/rejected proposal, records the master résumé in `master.synced.json`, closes readiness `master_synced`; exit 1 without a master résumé)
- `.venv/bin/careeros resume look-check` — exit 0 when the master résumé look is approved, else exit 7 (prepare-job Step 0; REQ-143)
- `.venv/bin/careeros resume approve-look` — records that you saw and approved how the master résumé looks (`profile/master.look.json` {rid, version, approved_at}); prints where its PDF is. Closes readiness `resume_look_approved` (prepare and apply exit 7 until then); a new master résumé or version resets it; exit 1 without a master résumé
- `.venv/bin/careeros view [--open]` — writes `data/views/<tab>.html` from data on disk (no AI, no network), linked as tabs: Setup checklist until its must-items are done, then Documents (résumés, saved answers, writing samples); Jobs (open action items, jobs by stage, last runs); Search (every job-search filter, its value, a sentence to say in chat to change it, and how many new postings each filter removed in the last `scout`, read from `data/scout_last.json`); Applications (newest first, 50). Prints the first tab's path, `--open` opens it
- `.venv/bin/careeros prune [--yes]`, `storage [--json] [--snapshot]`, `advise [--json]`, `advise apply <id>` (suggest-only; writes config/pipeline.yaml only on apply)
- `.venv/bin/careeros sync status [--remote template] [--no-fetch] [--json]|pull [--branch B] [--no-checks]|install-hook [--force]` — private copy vs the public template (status exit 0 in sync, 1 behind, 2 drift; pull exit 3 = conflicts; `.template-sync-keep` lists intentional differences)
- `.venv/bin/python -m careeros.qa data/jobs/<id>` — deterministic QA
- `.venv/bin/python templates/resume/render.py data/jobs/<id>/resume.json` — tex+pdf+txt
- `.venv/bin/python -m pytest -q`
- `.venv/bin/careeros safety ghost-items [--close-stale] [--dry-run]` — one `ghost_job` Action Item per dream company, listing its scored jobs that pass hard filters, meet `thresholds.min_fit_to_prepare` and still trip a ghost review flag (`safety check` no longer adds items). `--close-stale` first marks done, with a note and never deleting, open per-job `ghost_job` items the current rule would not raise; `--dry-run` (with it) only counts. Idempotent.
